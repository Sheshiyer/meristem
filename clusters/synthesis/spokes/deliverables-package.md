# Deliverables Package Skill

Package all brand outputs into organized delivery structure with validated asset manifest.

## Critical Lesson: Asset Manifest is Source of Truth

**NEVER package assets without validation.** The asset manifest must:
1. Be generated BEFORE packaging
2. List ALL assets with their origin (user-provided vs generated)
3. Verify ALL paths exist before packaging
4. Distinguish deterministic from AI-generated assets

## Prerequisites

- All prior waves and spokes complete
- `.brandmint/asset-manifest.json` generated and validated
- All skill outputs in `.brandmint/outputs/`

## Process

### Step 1: Generate Asset Manifest

Before packaging, generate and validate the complete asset manifest:

```bash
# Generate asset manifest from all sources
bm generate-manifest --config brand-config.yaml

# Output: .brandmint/asset-manifest.json
```

**Asset Manifest Structure:**

```json
{
    "generated_at": "2024-01-15T10:30:00Z",
    "brand_name": "Brand Name",
    "brand_slug": "brand-name",
    "version": "1.0.0",
    
    "user_provided_assets": {
        "description": "Assets provided by the user, not AI-generated",
        "assets": [
            {
                "id": "logo-primary",
                "path": "./user-assets/logo.png",
                "type": "logo",
                "exists": true,
                "deterministic": true,
                "required": true,
                "checksum": "sha256:abc123..."
            },
            {
                "id": "app-screenshot-home",
                "path": "./user-assets/screenshot-home.png",
                "type": "screenshot",
                "exists": true,
                "deterministic": true,
                "required": false
            }
        ]
    },
    
    "generated_assets": {
        "description": "Assets generated by AI during pipeline",
        "assets": [
            {
                "id": "hero-image-v1",
                "path": "./generated/hero-image-v1.png",
                "type": "hero",
                "exists": true,
                "deterministic": false,
                "wave": 4,
                "skill": "hero-images",
                "model": "gpt-image-2",
                "seed": 12345
            }
        ]
    },
    
    "validation": {
        "all_paths_exist": true,
        "required_assets_present": true,
        "missing_paths": [],
        "warnings": []
    }
}
```

### Step 2: Validate All Paths

**CRITICAL: Every path must be verified to exist before packaging.**

```bash
# Validate all paths in manifest
bm validate-manifest --config brand-config.yaml

# Output:
# ✓ User-provided assets: 4/4 exist
# ✓ Generated assets: 11/11 exist
# ✓ Required assets: all present
# ✓ Manifest valid, ready to package
```

**Validation rules:**

| Check | Action if Fail |
|-------|----------------|
| Required user-provided asset missing | **FAIL** - cannot package |
| Optional user-provided asset missing | **WARN** - skip asset, continue |
| Generated asset missing | **WARN** - regenerate or skip |
| Path exists but not in manifest | **WARN** - add to manifest or exclude |

### Step 3: Deliverables Inventory

Catalog all outputs to package, distinguishing by origin:

**Documents:**
| Item | Source | Origin |
|------|--------|--------|
| Brand Guidelines PDF | brand-documentation | Generated from outputs |
| Messaging Framework | messaging-framework.json | Pipeline output |
| Press Release | press-release.json | Pipeline output |
| Email Sequences | email-*.json | Pipeline output |

**Visual Assets:**
| Item | Source | Origin |
|------|--------|--------|
| Logo (primary) | user-provided OR logo-concept | User/Generated |
| Logo (variations) | logo-concept | Generated |
| App screenshots | user-provided | **Deterministic** |
| Photography | photography skills | Generated |
| Illustrations | illustration skills | Generated |
| Icons | icon-system | Generated |
| Patterns | pattern-library | Generated |
| Social media assets | social-media-assets | Generated |

**Digital:**
| Item | Source | Origin |
|------|--------|--------|
| Wiki site (built) | wiki-site-generator | Generated |
| NotebookLM artifacts | notebooklm-publishing | Generated |

**Data:**
| Item | Source | Origin |
|------|--------|--------|
| All JSON skill outputs | .brandmint/outputs/ | Pipeline outputs |
| Brand config | brand-config.yaml | User input |
| Asset manifest | asset-manifest.json | Generated |

### Bilingual zip (additive)

When `market.region: FR` or locales include both `en` and `fr`, the package **MUST** include both locale trees (copy, notebooklm sources, wiki docs) and the ZIP must contain both. Single-locale brands keep the previous layout and a single ZIP unchanged.

```bash
# Example artifact names
deliverables/[brand]-brand-package.zip          # full package including both locales
# Optional convenience extracts (if generated):
deliverables/[brand]-docs-fr.zip
deliverables/[brand]-docs-en.zip
```

### Step 5: Create ASSET-ORIGINS.md

Generate clear documentation of asset origins:

```markdown
# Asset Origins

This document explains which assets in this package are user-provided 
(deterministic) versus AI-generated.

## User-Provided Assets (Deterministic)

These assets were provided by the brand owner and have NOT been modified 
or generated by AI. They are exactly as provided.

| Asset | Location | Notes |
|-------|----------|-------|
| Primary Logo | 02-Logo/user-provided/logo-primary.png | Original brand logo |
| Home Screenshot | 06-Product/screenshots/screenshot-home.png | App screenshot |
| Dashboard Screenshot | 06-Product/screenshots/screenshot-dashboard.png | App screenshot |
| Product Hero Photo | 05-Photography/user-provided/product-hero.jpg | Product photo |

## AI-Generated Assets

These assets were generated by AI models during the brand pipeline.

| Asset | Location | Model | Skill |
|-------|----------|-------|-------|
| Logo Dark Variant | 02-Logo/generated/logo-dark.png | GPT-Image-2 | logo-concept |
| Hero Image | 05-Photography/generated/hero/hero-v1.png | GPT-Image-2 | hero-images |
| Lifestyle Photo 1 | 05-Photography/generated/lifestyle/lifestyle-1.png | GPT-Image-2 | lifestyle-photography |

## Why This Matters

- **User-provided assets** are your authentic brand materials
- **AI-generated assets** are creative suggestions that may need human review
- For regulatory or legal contexts, always verify asset origins
```

### Step 7: Package with Validation

```bash
# Package deliverables (validates all paths first)
bm package --config brand-config.yaml

# This will:
# 1. Load and validate asset manifest
# 2. Verify ALL paths exist
# 3. Create folder structure
# 4. Copy assets with origin markers
# 5. Generate MANIFEST.json
# 6. Generate ASSET-ORIGINS.md
# 7. Generate README.md
# 8. Create ZIP archive

# Output:
# ✓ Asset manifest valid
# ✓ 15/15 assets verified
# ✓ 8 documents verified
# ✓ Folder structure created
# ✓ Assets copied with origin markers
# ✓ MANIFEST.json generated
# ✓ ASSET-ORIGINS.md generated
# ✓ README.md generated
# ✓ ZIP created: brand-name-brand-package.zip (11.8 MB)
```

### Step 8: Final Verification

```bash
# Verify packaged contents
bm verify-package --path brand-name-brand-package/

# Output:
# ✓ All manifest entries exist
# ✓ All checksums match
# ✓ No extra files (all accounted for)
# ✓ ZIP integrity verified
# ✓ Package ready for delivery
```

## Quality Checklist

### Asset Validation
- [ ] Asset manifest generated and loaded
- [ ] ALL paths verified to exist before copy
- [ ] Zero hallucinated/non-existent paths
- [ ] Required assets all present
- [ ] Checksums computed for all files

### Origin Tracking
- [ ] User-provided assets clearly marked
- [ ] Generated assets clearly marked
- [ ] Deterministic vs AI-generated distinguished
- [ ] ASSET-ORIGINS.md generated
- [ ] Folder structure shows origin (user-provided/ vs generated/)

### Package Completeness
- [ ] All deliverables included
- [ ] Folder structure is logical
- [ ] README explains contents
- [ ] MANIFEST lists all files with metadata
- [ ] Logo in multiple formats (SVG, PNG)
- [ ] Colors in designer-friendly formats
- [ ] If bilingual/FR: both `en` and `fr` locale trees packaged

### Verification
- [ ] ZIP created and verified
- [ ] All manifest entries exist in ZIP
- [ ] Checksums match
- [ ] No missing or broken references
- [ ] Package ready for delivery
- [ ] If bilingual/FR: ZIP contains both locales
